# 통제된 로컬 파일럿 기반

현재 목표는 기업 운영 배포가 아니라, **합성 사례를 한 컴퓨터에서 반복 실행하고 근거와 검토 메모를 잃지 않는 검증 흐름**입니다. 실제 조직의 데이터·정책 책임자 검토, 승인된 테스트 시스템 및 보안 설계가 필요합니다.

## 실행 기록을 켜는 방법

```bash
python serve_workbench.py --workspace /absolute/private/location/ax-pilot
```

Windows에서는 본인만 접근 가능한 디렉터리 아래의 새 경로를 지정하세요. 저장 폴더는 소스 저장소 밖에 두세요. 기존 기본 명령은 계속 메모리 전용입니다. 로컬 주소 `http://127.0.0.1:8765`만 사용하며 서버는 외부 인터페이스에 바인딩하지 않습니다.

- 선택한 디렉터리에 SQLite 실행 기록을 저장합니다. 성공한 실행은 원본 결과, 설정, 선택·미실행 범위, 근거 hash와 함께 보존됩니다.
- 새로고침하거나 서버를 다시 시작해도 기록을 열 수 있습니다. 저장 기록은 현재 실행 결과와 별도 표시합니다.
- 저장이 실패하면 HTTP 실행 성공을 반환하지 않습니다. 완료 여부가 불확실한 경우 먼저 기록 목록을 확인하세요. 요청을 자동 재시도하지 않습니다.
- 실행을 마치고 결과를 저장하기 전에 프로세스가 중단되면 해당 실행 기록은 남지 않습니다. 실행 중 작업 추적, 중단 상태 영속화, worker 재개는 미구현입니다. 저장한 결과도 HTTP 응답 전달이 불확실하면 목록에서 확인해야 합니다.
- 기록은 자동 삭제되지 않습니다. 최대 100회 실행을 보관하며 한도에 도달하면 새 실행 저장을 거부합니다. 보존이 필요하면 서버 종료 후 폴더 전체를 별도 보관하고, 새로운 전용 폴더로 시작하세요.
- 운영 중인 데이터베이스 파일을 임의로 복사하지 마세요. 서버를 종료한 상태에서 전체 폴더를 백업하고, 복원 후 무결성 검사를 실행하세요. 이 버전에는 자동 백업·보존 정책·복구 서비스가 없습니다.

## 로컬 검토 기록

상태는 `UNREVIEWED`(미검토), `REVIEWED`(검토 메모 완료), `CHANGES_REQUESTED`(수정 요청)입니다. 검토 요청은 정확한 실행 hash와 현재 revision을 함께 보내야 합니다. 다른 탭에서 먼저 수정한 경우 충돌을 표시하며 이전 상태를 덮어쓰지 않습니다. 검토 이력은 추가 방식으로 남깁니다.

**검토 표식은 사용자 인증, 검토자 신원 증명, 전자서명, 직무 분리, 배포 승인 또는 실제 정책의 정확성 확인이 아닙니다.** 일부 사례 통과, 미확인 입력, 검토 메모 상태를 합쳐 전사 정상으로 표시하지 않습니다. 실제 주문·고객·직원 정보, 비밀 키, 내부 기밀은 메모에 넣지 마세요.

## 무결성과 재현성

```bash
python manage_evidence.py --workspace /absolute/private/location/ax-pilot verify
python manage_evidence.py --workspace /absolute/private/location/ax-pilot list
python manage_evidence.py --workspace /absolute/private/location/ax-pilot replay RUN_ID
```

- `verify`는 저장된 전체 실행 내용과 추가 이력의 hash 연결을 검사합니다. 읽기·쓰기 모두 같은 검사를 수행하며 손상된 저장소를 자동 복구하거나 통과로 보지 않습니다.
- `replay`는 명시적으로 선택한 합성 실행만 현재 등록된 모의 어댑터로 재현합니다. 저장 파일 안의 URL·코드·경로·외부 어댑터를 실행하지 않습니다. 원본이나 검토 상태는 바꾸지 않습니다.
- `MATCH`는 동일 근거에서 결정적 결과가 다시 나온다는 뜻입니다. 미확인이나 부분 범위는 그대로 유지됩니다. 근거 버전이 달라지면 `INCOMPATIBLE`, 결과가 달라지면 `DIFFERENT`로 반환합니다.
- 프로세스 시작 후 실행 소스가 변경되면 실행 전후 검사로 차단합니다. 업그레이드할 때 서버를 종료하고, 파일을 바꾼 후 다시 시작하세요. 실행 중 소스 파일을 편집하지 마세요.

Hash 연결은 **서명도, 변경 불가능한 감사 저장소도 아닙니다**. 파일 쓰기 권한자가 전체 데이터와 hash를 다시 쓰거나 마지막 이력을 제거한 사실을 독립적으로 증명하지 못합니다. 소스 변경 검사 또한 악의적 로컬 사용자나 실행 중 파일 교체·복구 공격을 막는 보안 경계가 아닙니다. 독립 보관된 checkpoint와 인증된 감사 시스템은 후속 과제입니다.

## 데이터 보호 경계

- Python 표준 라이브러리만 사용하며 외부 API·LLM·텔레메트리로 데이터를 보내지 않습니다.
- Host/Origin/Fetch-Metadata, 고정된 경로, 요청 길이·JSON 검사와 CSRF 토큰을 유지합니다. CSRF 토큰은 사용자 인증이 아닙니다. 동일 컴퓨터의 다른 프로그램도 요청할 수 있습니다.
- POSIX의 새 저장 폴더/파일은 소유자 전용으로 생성하며 위험한 권한이나 symlink를 거부합니다. Windows ACL과 디스크 암호화는 운영자가 확인해야 합니다. 애플리케이션 암호화는 제공하지 않습니다.
- 리뷰 메모와 JSON 보고서는 평문입니다. 파일·백업 접근 권한과 다운로드 후 공유는 운영자의 책임입니다. 실제 업무 데이터 입력을 승인하는 기능은 아닙니다.
- 실패 응답에는 내부 경로·traceback·요청 내용을 포함하지 않습니다. 무결성 오류는 기존 기록을 보존한 채 중지합니다.

## 실제 기업 파일럿으로 넘어가기 전

| 단계 | 수용 조건 | 아직 필요한 결정 |
|---|---|---|
| 1. 합성 로컬 검증 | 저장·재시작·손상 차단·충돌·재현·범위 구분 테스트 | 이 버전의 구현 범위 |
| 2. 업무 기준 확정 | 정책 담당자와 독립 QA가 정답·시행일·예외·누락 범위를 서명된 절차로 확인 | 대상 업무, 책임자, 위험도, 성공/실패 기준 |
| 3. 비식별 테스트 연결 | 승인된 sandbox 1개, 읽기/쓰기 범위, 멱등키, timeout 후 독립 관찰, egress allowlist | 기업 계정·데이터 사용 및 외부 연동 권한 |
| 4. 조직 보안 | SSO/RBAC, 조직 격리, 최소 권한, 비밀 관리, 암호화, 인증된 검토자·직무 분리 | 배포 구조, 보안·개인정보 검토 |
| 5. 운영 검증 | 접근 감사, 보존·삭제 정책, 복구 훈련, 부하·장애 테스트, 감시와 담당자 | RPO/RTO, SLO, 장애 대응·운영 승인 |

2~5단계는 구현 완료나 승인된 것으로 주장하지 않습니다. 현재 도구를 방화벽 포트 개방, 리버스 프록시, 터널로 공유 서비스로 만들지 마세요.
