# 6분 시연 설계

현재는 시연 설계이며 실행 영상·작동 UI가 아니다. 구현 후 화면의 모든 수치는 실제 실행 기록을 읽어 표시한다.

| 시간 | 보여줄 장면 | 전달할 의미 |
|---|---|---|
| 0:00~0:35 | 반품 정책 14일→30일과 적용 대상 | 기업의 업무 변경 한 건 |
| 0:35~1:15 | 전후 원문·조건·시행일 검토 | AI 추출을 확인 가능한 기준으로 전환 |
| 1:15~1:55 | FAQ·모의 API·상담 AI의 영향 후보 | 설명 자료와 실행 대상의 연결 |
| 1:55~2:45 | 20일 사례의 이전/후보 실행과 실패 | 새 기준이 실제 처리에 반영되지 않은 문제 |
| 2:45~3:25 | FAQ 수정 후 재실행: API 실패 잔존 | 일부 수정만으로 업무가 해결되지 않음 |
| 3:25~4:15 | API 수정, 기존 배송·주문제작 사례 검증 | 의도한 변화와 유지할 예외의 동시 검증 |
| 4:15~5:05 | 제조·금융 팩의 사례와 같은 결과 형식 | 제한된 업무에 대한 공통 엔진 재사용 |
| 5:05~6:00 | 근거·재현 명령·미확인 범위·기준선 결과 | 검증 수준과 실무 적용의 다음 조건 |

## 시연 전 준비

- 고정된 입력·원문·artifact version을 선택하고 초기화한다.
- 정상 후보, FAQ만 수정한 후보, 프로그램까지 수정한 후보를 별도 버전으로 보존한다.
- 실패를 실제 어댑터 결함으로 재현한다. 화면에서 임의로 ‘실패’를 토글하지 않는다.
- 실시간 모델 호출 실패에 대비한 녹화/캐시 모드는 명확히 표시한다. 재생을 현재 실시간 실행이라고 말하지 않는다.
- 기준선 측정이 없으면 마지막 화면을 ‘평가 계획’으로 표시하고 가짜 수치를 넣지 않는다.

## 화면에서 꼭 구분할 것

확인된 관계 / 추론 관계 / 연결되지 않은 대상, 실제 관찰 / 모델 주장, 정상 업무 거절 / 시스템 실패, 진단 assertion 통과 / 업무 판단 보류, 합성 자료 / 실제 자료.
