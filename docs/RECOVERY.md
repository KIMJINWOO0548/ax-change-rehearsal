# 로컬 기록 백업과 복구 훈련

이 기능은 합성 로컬 파일럿의 기록 유실에 대비한 도구입니다. 네트워크 공유 서버, 기업 계정, 실제 고객 데이터, 인증된 승인 시스템을 추가하지 않습니다. 백업에는 실행 보고서와 검토 메모가 **평문**으로 들어갑니다. 비밀이나 개인정보를 넣지 마세요.

## 명령

본인만 접근 가능한 위치를 사용하고, 소스 저장소 밖에 백업과 복원 폴더를 두세요. 모든 대상 폴더는 아직 존재하지 않는 새 경로여야 합니다. 기존 폴더, 비어 있는 기존 폴더, 기존 작업 공간을 덮어쓰지 않습니다.

```bash
python manage_recovery.py backup --workspace /private/ax-pilot --destination /private/ax-backup-001
python manage_recovery.py inspect --source /private/ax-backup-001
python manage_recovery.py restore --source /private/ax-backup-001 --destination /private/ax-restored-001
python manage_evidence.py --workspace /private/ax-restored-001 verify
python serve_workbench.py --workspace /private/ax-restored-001
```

Windows에서는 해당 컴퓨터의 절대 경로를 사용하고 폴더 ACL·디스크 보호를 직접 확인하세요. 이 애플리케이션은 Windows ACL을 변경하거나 디스크 암호화를 켜지 않습니다.

### 백업

SQLite의 일관된 snapshot을 만들어 복사본의 schema, 기록 hash 연결, 집계와 snapshot 복사본 데이터베이스 checksum을 검증합니다. 성공 출력에는 내용이나 메모 대신 checksum, ledger head와 건수만 표시합니다. 업무 데이터가 변경되는 도중 파일을 단순 복사하는 방법과 구분합니다.

백업 디렉터리는 `evidence.sqlite3`와 `manifest.json`으로 구성됩니다. manifest가 없거나 파일 구성이 다르거나 checksum이 맞지 않으면 완료된 백업으로 보지 않습니다. 수동으로 파일을 추가·편집하거나 manifest만 복사하지 마세요. 백업 폴더를 서버 작업 공간으로 직접 여는 것도 거부합니다. 먼저 새 폴더에 복원해야 합니다.

### 검사

`inspect`는 백업을 읽기 전용으로 검사합니다. 백업의 파일·schema·ledger를 확인하며, 검토 표식을 새로 만들거나 원본을 고치지 않습니다. 불완전한 백업이나 복구되지 않은 SQLite sidecar에 의존하는 입력은 거부합니다. 임의 SQL, 코드, URL, 압축 파일을 가져오는 기능이 아닙니다.

### 복원

검증된 백업만 새 작업 공간으로 복원합니다. 기존 작업 공간은 보존하며 복원본의 실행·검토 이력과 hash 연결을 다시 확인합니다. 실패한 복원본을 기존 원본 대신 사용하지 마세요. 원본이나 손상된 백업을 자동 초기화·삭제·수리하지 않습니다. 실패로 새로 만들어진 폴더는 조사할 수 있도록 남습니다. 미완료 표식이 있는 폴더는 서버가 작업 공간으로 열지 않습니다. 같은 경로에 재시도해 덮어쓰지 말고 새 경로를 선택하세요.

복원 후 `manage_evidence.py verify`로 전체 기록을 확인하고 화면에서 실행 ID, 선택/미실행 범위, 검토 revision을 확인하세요. 등록된 모의 결과를 다시 실행하려면 `manage_evidence.py ... replay RUN_ID`를 명시적으로 사용합니다. 소스가 업그레이드되어 과거 결과와 근거 버전이 다르면 `INCOMPATIBLE`이며, 과거 기록을 통과로 바꾸지 않습니다.

## 복구 훈련 체크리스트

1. 합성 사례를 실행하고 검토 메모를 하나 남깁니다.
2. 새 경로로 백업한 뒤 `inspect` 성공과 출력된 checksum·head·건수를 기록합니다.
3. 원본을 지우지 않은 상태에서 별도 새 경로로 복원합니다.
4. 실행 ID, 보고서 hash, 부분 범위, 검토 상태·revision·메모가 그대로인지 확인합니다.
5. 복원본을 사용하는 별도 로컬 서버에서 과거 기록을 열어 확인합니다. 현재 결과나 운영 승인으로 표시하지 않습니다.
6. 백업 파일 일부를 수정한 별도 시험 사본은 검사/복원이 실패하는지 확인합니다. 보존용 원본 백업에는 손대지 마세요.

Format 1 제한은 데이터베이스 128 MiB, manifest 4 KiB, 이벤트 payload 1 MiB, 실행 100개, 실행당 검토 1000개입니다. 논리 데이터베이스가 크기 한도를 넘는 쓰기는 commit 전에 거부합니다. 암호화·압축·임의 파일은 지원하지 않습니다.

자동 시험은 일관된 snapshot, 저장/검토 동시성, 손상·누락·예상 외 schema, 경로/권한, 덮어쓰기 거부, 실패 시 파일과 연결 정리를 다룹니다. 실제 실행한 시험 수와 환경은 `VALIDATION.md`를 따릅니다.

## 보장하지 않는 것

- checksum과 ledger hash는 서명이나 외부에 고정된 감사 증거가 아닙니다. 파일 소유자가 데이터와 hash를 함께 다시 쓰는 것을 인증된 방식으로 탐지하지 못합니다.
- 원본과 같은 디스크의 백업은 디스크 고장·분실·랜섬웨어에 독립적이지 않습니다. 조직의 승인된 별도 보관 위치, 암호화, 접근 권한 및 보존 정책은 별도로 필요합니다. 이 도구는 원격 위치로 자동 전송하지 않습니다.
- 백업의 포함 범위는 완료 후 저장된 실행과 검토 이력입니다. 실행 중이던 작업, 아직 저장되지 않은 결과, 프로세스 메모리, 외부 시스템 상태는 복구하지 않습니다.
- 성능/부하 benchmark, 장애복구 목표(RPO/RTO), 자동 스케줄, 자동 보존·삭제, 키 관리, 인증된 검토자나 다중 조직 서비스는 제공하지 않습니다.
- 로컬 파일을 악의적으로 교체했다가 되돌리는 사용자, OS/프로세스 손상이나 공격을 막는 샌드박스가 아닙니다. 공유 컴퓨터나 인터넷 서비스로 배포하지 마세요.
